# 検証用プロトタイプ（メロディを育てて MIDI で持ち出す）

- Status: approved
- Date: 2026-10-26
- Related: なし（課金・アカウントは本プロトタイプの判定後に別 spec）

## Problem and goal

MeloBreed が売れるかは、市場調査では分からない 3 点にかかっている。(1) 3 世代以内に「使える」メロディが出るか、(2) 使った人が翌週も戻るか、(3) 書き出した人が有料版に反応するか。これを 2〜3 週間で作れる最小のプロトタイプで測り、事前に決めた基準で継続・方向転換・撤退を決める。

想定ユーザー（暫定）: 趣味〜セミプロのビートメイカー / DTMer（ボカロP を含む）。日本の DTM・ボカロ界隈と英語圏（Reddit 等）の両方で公開する。

## Scope

- In scope: ジャンル・キー・スケール・テンポの指定、8 候補の試聴（単体・連続再生、再生時のみのコード伴奏）、親の選択と次世代の繁殖、世代を戻る操作、MIDI 書き出し、ブラウザ内での続きの再開、日英 UI、同意バナーと PostHog 計測、価格付き「Pro（準備中）」画面と Supabase へのウェイトリスト保存、プライバシーポリシー。
- Out of scope: アカウント・ログイン、決済（Stripe）、クラウド保存、共有リンク、コード・ベース・多声、ノートの手動編集、WAV 書き出し、DAW プラグイン、学習済み ML モデル、Playwright E2E、PWA・オフライン。

## Requirements

1. 初回はブラウザの言語が日本語なら日本語 UI、それ以外は英語 UI。画面上でいつでも切り替えられる。
2. 開始前にジャンルプリセット（Trap / Hip-hop、Lo-fi、J-pop / ボカロ、EDM / House）、キー（12）、スケール（メジャー、ナチュラルマイナー、ドリアン、メジャーペンタ、マイナーペンタ）、BPM（60〜180）を選べる。BPM とスケールの初期値はプリセットが決める。
3. 1 世代は 8 候補。各候補は 4/4 拍子・4 小節・単旋律のメロディ。
4. 候補をタップすると、その候補だけを指定 BPM で再生する（再生中に別の候補を押すと前の再生は止まる）。「すべて再生」で 8 候補を順に再生し、再生中の候補を強調する。各候補が内部に持つコード進行を小さな音量で伴奏として鳴らせる（ON/OFF 可、書き出す MIDI には含めない）。
5. 1〜3 個を親として選び「次の世代」で 8 個の新しい候補を作る。親 1 個なら変異のみ、2〜3 個なら交叉＋変異。「前の世代に戻る」で直前の世代と選択状態を復元できる。
6. 各候補から MIDI ファイル（.mid）を書き出せる。中身はメロディのみで、スウィングをかけずにクオンタイズしたまま書き出す（グルーヴは DAW 側でかける）。
7. 進行中のセッション（設定・全世代の候補・選択・世代番号）はブラウザ内に保存し、再訪時に続きから再開できる。「新しく始める」で破棄する。
8. 初回訪問時に計測の同意バナーを出す。同意した人だけ PostHog で匿名 ID による計測を行う。拒否してもアプリは全機能使える。フッターから同意を変更できる。
9. 「Pro（準備中）」をヘッダーと MIDI 書き出し直後に表示する。Pro 画面には予定機能と単一価格（英語: $6.99/月・$49/年、日本語: ¥980/月・¥7,800/年）を表示し、リリース通知用のメールアドレスを受け付ける。
10. LP 文言で「学習データを使わない」「あなたの選択だけで育つ」を打ち出す（本プロトタイプのエンジンには学習済みモデルを含めない）。
11. 日英のプライバシーポリシーを用意し、同意バナー・フッター・ウェイトリストのフォームからリンクする。
12. iOS Safari と Android Chrome の最新版で全機能が動く。

## Acceptance criteria

- [ ] AC1: 言語が `ja` のブラウザで初めて開くと日本語 UI、`en-US` なら英語 UI。切替後は全文言が切り替わる。日英の文言辞書はキーが完全に一致する（単体テスト）。
- [ ] AC2: プリセット・キー・スケール・BPM を選んで開始すると、第 1 世代の 8 候補が表示される。プリセットを変えると BPM とスケールの初期値が変わる。
- [ ] AC3: 候補をタップするとその 4 小節が指定 BPM で鳴る。別の候補をタップすると前の音が止まる。「すべて再生」で 8 候補が順に鳴り、再生中の候補が強調される。コード伴奏の ON/OFF が再生に反映される（iOS Safari・Android Chrome で手動確認）。
- [ ] AC4: 選択 0 個では「次の世代」が押せない。4 個目は選べない。「次の世代」で世代番号が 1 増えて 8 個の新候補になる。「前の世代に戻る」で直前の候補と選択が完全に復元される。
- [ ] AC5: エンジンの不変条件（単体テスト、seed を変えて 500 回以上）。全ノートが指定スケール内・プリセットの音域内。開始と長さは 16 分グリッド上で、4 小節に収まる。ノートは重ならない。同一世代の 8 候補は互いに異なる。
- [ ] AC6: 同じ seed・同じ設定・同じ選択の列からは常に同じ候補列が出る（単体テスト）。
- [ ] AC7: 子の各候補 C は、いずれかの親 P について、(音高, 開始) の集合で `2·|C∩P| ≥ |C|` を満たす。子の音数は主の親の ±25% 以内（単体テスト、seed を変えて 500 回以上）。
- [ ] AC8: 書き出した .mid は SMF フォーマット 0・480 PPQ・テンポが BPM と一致し、ノートの音高・開始・長さが候補と一致する（単体テストでバイト列を検証）。GarageBand と、FL Studio・Ableton Live・Logic Pro のいずれか 1 つで読み込み、音高とタイミングが正しい（手動）。
- [ ] AC9: 再読み込みや再訪で最後の世代から再開できる。ブラウザのストレージが使えない場合（プライベートモード等）も、再開以外の機能はエラーなく動く。
- [ ] AC10: 同意前は PostHog へのネットワーク通信が 1 件も発生しない（DevTools で確認）。同意後はイベントが届く。拒否時は届かない。
- [ ] AC11: 同意したユーザーで次のイベントが PostHog に届く。`session_started`（preset, key, scale, bpm, locale）、`candidate_played`、`generation_bred`（generation, parentCount）、`midi_exported`（generation, preset）、`pro_viewed`（source: header | after_export）、`waitlist_submitted`。判定の ①〜④ を出す PostHog のファネル・リテンションの集計を用意する。
- [ ] AC12: Pro 画面に予定機能と、表示言語に応じた価格が表示される。有効なメールを送ると Supabase に email・locale・source・作成日時が 1 行保存され、完了表示になる。不正な形式はその場でエラーを出し、保存しない。登録済みのメールは同じ完了表示で行は増えない。ボット除けの隠し項目が埋まっていれば保存しない。通信・DB エラー時はエラー表示と再試行ができ、画面は壊れない。
- [ ] AC13: 公開用キーではウェイトリストのテーブルを読み出せない（REST で select して 0 件または拒否になる）。
- [ ] AC14: 幅 375px で横スクロールが出ず、8 候補が 2 列で表示され、タップ対象は 44px 以上（手動）。
- [ ] AC15: `npm run verify` と `npm run build` が通る。クライアントのバンドルに `NEXT_PUBLIC_*` 以外の環境変数が含まれない。`src/engine/` の ESLint 制約は変えない。

## 継続・撤退の判定（固定）

- 判定時点: 公開から 2 週間、かつ有効セッション（同意済みで第 1 世代を生成した人）が 100 以上。2 週間で 100 に届かなければ最大 4 週間まで延長する。それでも届かない場合は「集客が成立しない」という結果として扱い、テスト参加者への聞き取りで判断する。
- ① 開始した人の 30% 以上が第 3 世代に到達する。② 開始した人の 10% 以上が MIDI を書き出す。③ 書き出した人の 15% 以上が、初回訪問の 7〜14 日後に再訪する。④ 書き出した人の 3% 以上が Pro 画面を開く。
- 全達成なら継続（アカウント・課金の spec へ）。①か②が未達なら、方向転換か撤退。③か④だけ未達なら、改善して 1 回だけ 2 週間再測定し、そこで決める。
- 補助: 20〜30 人のテスト参加者に「使えそうなメロディが出たか」「何世代目か」を聞き取り、①②の解釈に使う。

## Design notes

- エンジン（`src/engine/`、純 TS、`Rng` 注入）。詳細な設計と根拠は `docs/plans/2026-10-26-validation-prototype.md` にある。
  - 遺伝する表現は平坦な音符列 `Note { degree, start, duration }`（音高はスケール度数、開始と長さは 16 分ステップ、4 小節 = 64 ステップ）と `meta.progression`（暗黙のコード進行。第 1 世代で決めて主の親から継承し、変異させない）。
  - `render` は度数→MIDI 音高の変換だけを行い、`validate` が AC5 を検査する。描画後の補正はしない。
  - 第 1 世代はモチーフ×形式（AABA' など）×変形（反行・逆行・ゼクエンツ）×コード進行で組み立てて平坦化する。初期世代の質がこの検証の最大の変数。
  - 繁殖は音楽的な変異（度数 ±1/±2、分割・結合、開始のずらし、小節単位の変形とコピー）と「主の親＋提供小節」型の交叉。子のプールから必須条件（AC5、AC7、重複なし、評価の足切り）で絞り、変化量の段階ごとの枠と多様性（MMR）で 8 個を選ぶ。
  - `midi.ts`: `Melody` と BPM から SMF フォーマット 0 の `Uint8Array` を作る（I/O なしの純データ変換なのでエンジン内に置ける）。
  - スウィングは再生時だけのタイミング変換として扱う。
  - 制約: 16 分グリッドなので、3 連符は今回は表現できない。
- UI（`src/app/`）: 設定画面 → 世代画面（8 候補グリッド、選択、次の世代、戻る、書き出し）→ Pro 画面（モーダル）。i18n の具体的な方式（ルートで分けるか、クライアントの辞書にするか）は計画段階で Next.js 16 のドキュメントを確認して決める。seed は UI 側で `crypto.getRandomValues` で作り、エンジンへ渡す。
- 音声: Tone.js をクライアントで動的 import し、最初のタップで `Tone.start()` する。iOS のマナーモードで音が出ない場合がある旨を表示する。
- 保存: セッションはプレーンデータとして localStorage に保存する（自分のデータの機能的な保存なので同意対象外。計測 ID は同意後のみ）。
- ウェイトリスト: Supabase の `waitlist(id, email unique, locale, source, created_at)`。ルートハンドラーでサーバー側検証してから insert する。RLS で匿名の select を禁止する。
- 追加する依存: `tone`、`posthog-js`、`@supabase/supabase-js`。環境変数は `.env.example` にプレースホルダーだけ置く。
- 検討して外した案: Vercel Analytics（匿名ユーザーの再訪が追いにくく、カスタムイベントは有料）、外部フォーム（クリックとの紐付けができない）、価格 A/B（サンプルが半分になり判定が不安定）。

## Verification plan

- Automated: `src/engine/*.test.ts` で AC5〜AC8 を検証し、i18n 辞書のキー一致（AC1）もテストする。`npm run verify`、`npm run build`。
- Manual: iOS Safari・Android Chrome での試聴と書き出し（AC3、AC8、AC14）、DAW への読み込み（AC8）、DevTools で同意前の通信がないこと（AC10）、PostHog のライブイベント（AC11）、Supabase の行と RLS（AC12、AC13）。

## Risks and rollback

- 初期世代の質が低いと ①② が未達になる。これは検証したい点そのものなので、公開前に 5 人程度で試聴し、`generate.ts` の事前分布を調整してから公開する。
- Vercel の Hobby プランは非商用利用に限られる。価格付きの Pro 画面を公開する前に、Pro プランが必要か確認する。
- メールアドレスは個人情報。保存項目を最小にし、削除依頼の窓口をプライバシーポリシーに書く。撤退時はテーブルと PostHog プロジェクトを削除する。
- iOS は Web Audio の初回再生がタップ必須で、マナーモードでは無音になる。表示で案内する。
- ロールバック: 既存機能がないため、コミットの revert と Vercel の旧デプロイへの切り戻しで戻せる。

## Open questions

- 「学習データを使う ML は入れない」を長期の製品原則にするか（本プロトタイプでは事実として成り立つので文言に使う）。
- テスト参加者 20〜30 人の集め方と、公開する場所・日程（運用面。実装には影響しない）。
- プライバシーポリシーに載せる運営者名と連絡先。
- PostHog のデータ保存リージョン（US / EU）。環境変数で切り替えられるので実装には影響しない。
- 公開ドメイン。

# 実装計画: 検証用プロトタイプ

仕様: `docs/specs/2026-10-26-validation-prototype.md`（承認済み）。ブランチ `feat/validation-prototype` を `chore/scaffold` から切る（scaffold が main に入ったら rebase）。コミット・push はユーザーの指示があるまでしない。

## Context

MeloBreed が売れるかを、2〜3 週間で作る最小プロトタイプで測る。核心は「3 世代以内に使えるメロディが出るか」で、これはエンジンの設計（表現・初期世代・遺伝的操作・候補の選び方）でほぼ決まる。先行研究を調べて方針を立て、Plan エージェントによる独立レビューで保証の穴を潰した。

## エンジン方針（調査と設計レビューの結論）

| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 出発点                     | 第 1 世代から音楽として成立したメロディを出す。ランダムな音から進化させない                                                                                                                                                                                                                                                       | DarwinTunes（PNAS 2012）は 6,931 人の評価で 2,513 世代かけて音楽らしくなった。1 人で数世代では無理                                                                                                                       |
| 第 1 世代の作り方          | モチーフ（1〜2 小節）× 形式（AABA'、ABAB' など）× 変形（反行・逆行・ゼクエンツ）× 暗黙のコード進行で組み立て、音符列に平坦化する                                                                                                                                                                                                  | GenJam（Biles）の小節＋フレーズの階層表現。反復と変奏が構造として入る                                                                                                                                                    |

### 保証のしくみ（AC5〜AC7）

- AC7 の定義を整数で固定する: 子 C と親 P の (音高, 開始) の集合について `2·|C∩P| ≥ |C|`。`critic.ts` の 1 関数をフィルタとテストで共用する。子の音数は主の親の ±25% 以内に制限する（音を大量に削って比率を稼ぐ抜け道を塞ぐ）。
- 子の必須条件: `validate` を通る、同一世代で重複しない、どれかの親に対して AC7 を満たす、すべての親に対して (音高, 開始) の変化 1 つ以上か長さの変化 2 つ以上、評価が親基準の足切り以上。
- プールは 32 個ずつ作り、24 個が条件を通るか 256 回試すまで続ける（上限つき）。
- 8 個に満たないときの最終手段: 主の親の描画済みメロディに対する決定的な単一編集のリスト（最終音以外の各音×度数 {+1, −1, +2, −2} → 長さ ±1 ステップ）。`validate` で最低音数 8・音域 12 半音以上を強制しているので、候補は 2(N−1) ≥ 14 通り以上あり、各候補は親と 7/8 以上を共有する。よって 8 個は必ず埋まる。最悪ケース（8 音すべてが音域の上端・強拍）をテストの固定データにする。
- 決定性（AC6）: `deriveSeed(seed, selected)` は親の選択をビットマスクにして順序に依存させず、`Math.imul` だけを使う 32bit ハッシュ（fmix32）で混ぜる。加算での seed 派生は禁止（mulberry32 では seed と seed+定数が 1 ステップずれた同じ列になる）。プールの子ごとに `createRng(childSeed(genSeed, i))` を作り、ある子の再試行が他の子に波及しないようにする。評価値と距離は四則演算だけで計算し、`Math.round(1e6·x)` の整数で比較し、同点はプールの番号で決める（ブラウザ間で `Math.exp` などの結果がずれるのを避ける）。ゴールデン値テストを `rng.test.ts` と同じ形で置く。既存の `createRng`（`src/engine/rng.ts`）の出力は変えない。
- 保存は seed からの再生ではなく、メロディそのものを保存する: `{schemaVersion, engineVersion, settings, generations: [{seed, candidates, selected}]}`。評価ルールを後で調整しても、ユーザーの保存済みメロディが変わらない。読み込み時に全メロディを `validate` し、1 つでも違反していればセッションを破棄する（AC9）。100 世代を上限とし、容量超過は捕まえて無視する。

### 第 1 世代で聴き手が気づく点への対策

- 音数の密度は 1 秒あたりの音数（約 1.5〜5）で持ち、BPM から 1 小節あたりの音数に換算する（遅い BPM でスカスカ、速い BPM でせわしない、を防ぐ）。最初の音は 2 拍目までに鳴らす。
- 8 候補が「強拍の音と終止」で似て聞こえるのを避ける: 最終音は主音を優先しつつ I の 3 度・5 度も許す。終止の位置（4 小節目の 1 拍目・3 拍目・先取り）と音域を 8 候補に散らす。密度（疎・中・密）×輪郭（山型・上行・下行）×形式に枠を設けて MMR で選ぶ。
- 「新しく始める」は設定を残したまま、1 タップで新しい第 1 世代を出す。

## ファイル構成

エンジン（`src/engine/`、純 TS・外部 import 不可・`Rng` 注入）

- `music.ts`: キー、5 スケールと親スケール、度数⇄MIDI 音高（負の度数の剰余に注意）、ローマ数字→コードトーン（コード ∩ スケール）
- `presets.ts`: 4 ジャンルの BPM 初期値・範囲、既定スケール、音域（12 半音以上）、密度（音/秒）、リズムテンプレート、シンコペーション、同音連打の上限、形式の候補、スウィング量、スケール系統ごとのコード進行候補、選択の重み（0.35/0.65、段階の境界）。調整値はここに集約する
- `melody.ts`: `Note`・`Melody`（`notes`、`meta.progression`）の型、`render`（度数→MIDI 音高）、`validate`
- `generate.ts`: 第 1 世代（モチーフ×形式×変形×進行 → 平坦化 → 必須条件 → 枠つき MMR で 8 個）
- `operators.ts`: 変異と交叉。各操作は変えた音数を返す
- `critic.ts`: 評価ルール、`sharesHalf(child, parent)`（AC7）、距離 `D = 0.5·オンセットのハミング距離/和集合 + 0.5·両方鳴っているステップでの min(|度数差|, 3)/3 の平均`
- `breed.ts`: プール → 必須条件 → 段階の枠（親 1 個: 近い 3・中 3・遠い 2。親 2〜3 個: 各親が主の親になる子を 2 個以上、純粋な交叉を 3 個以上）→ MMR → 最終手段
- `seed.ts`: `deriveSeed`、`childSeed`
- `session.ts`: `startSession(settings, seed)` / `breedNext(generation, selected, settings)` / `serialize` / `deserialize`（validate つき）
- `midi.ts`: `toMidiFile(melody, bpm): Uint8Array`。SMF フォーマット 0、480 PPQ（16 分 = 120 tick）、テンポ・拍子のメタイベント、ノートは ch1。スウィングなしのクオンタイズ済み。依存は追加しない
- テスト: 各ファイルの横に `*.test.ts`。500 個以上の seed を 4 プリセット×12 キー×5 スケールの全組み合わせ（240 通り）に散らす。ランダムに 1〜3 個を選ぶ 3 世代の連鎖、ほぼ同一の 3 親、最小の親（8 音）の固定データ。セッションは繁殖のたびに JSON を往復させてテストする

UI（`src/app/`。既存の `layout.tsx` と `page.tsx` を `[lang]/` の下に移す）

- `src/proxy.ts`: `/` と言語なしの URL を、cookie（手動切替の記憶）→ `Accept-Language`（`ja` 系なら ja、それ以外は en）の順で `/ja` か `/en` にリダイレクトする。matcher で `api`・`ingest`・`_next`・静的ファイルを除外する（`api` を外さないと `POST /api/waitlist` が `/en/api/...` に飛ばされる）。言語判定は自前の小さな関数にしてテストする（`negotiator` 等は入れない）
- `src/app/[lang]/layout.tsx`: `LayoutProps<"/[lang]">`、`generateStaticParams` → `[{lang:"ja"},{lang:"en"}]`（`next.config.ts` で Cache Components が有効なので必須）、`hasLocale` で絞り込み、範囲外は `notFound()`、`<html lang>`
- `src/app/[lang]/dictionaries/{ja,en}.json` と `dictionaries.ts`: サーバー側で読み込み、必要な文言を props でクライアントに渡す。キー一致テスト（AC1）
- `src/app/[lang]/page.tsx`: LP 文言（学習データ不使用・あなたの選択だけで育つ）＋ `BreedApp`
- `src/app/_components/`: `BreedApp`（状態は `useReducer`、セッションを localStorage に try/catch で保存）、`SetupForm`、`CandidateGrid` / `CandidateCard`（再生・選択・書き出し、SVG のミニピアノロール）、`ProModal`、`ConsentBanner`、`LanguageSwitcher`
- `src/app/_audio/player.ts`: `BreedApp` のマウント時に `import("tone")` を先読みし、再生タップの中では同期的に `Tone.start()` を呼ぶ（`await import` を挟むと iOS でジェスチャー扱いが切れる恐れがある）。再生は `Tone.getTransport()` ＋ `Tone.Part` で行い、別候補を押したら `stop()`・`cancel(0)`・`dispose()` で確実に止める。スウィングは Transport 経由の発音にしか効かないので Part 方式が必須。8 候補は同じ音色で比べる（ジャンルごとに `Synth` / `MonoSynth` の音色を変える、強拍のアクセント、短いリリース）。コード伴奏は候補の `meta.progression` を小さな音量のパッドで鳴らし、ON/OFF できる。連続再生は 8 候補を順に鳴らし、再生中の候補を強調する。iOS は `navigator.audioSession` があれば `type = "playback"` にしてマナーモードでも鳴らし（iOS 17 以降）、それ以外は案内文を出す
- `src/app/_analytics/`: 同意状態は localStorage に保存。同意するまでは `posthog-js` を import も init もしない（init するだけで `/flags` などへの通信が起きるため）。同意後の init 設定は、永続化を既定のまま（再訪の計測に匿名 ID が必要）、`advanced_disable_flags`、`disable_surveys`、`disable_session_recording`、`autocapture: false`、`person_profiles: "always"`（匿名ユーザーのリテンションを確実に出すため）。同意を取り消したら `opt_out_capturing()` と `reset()` を呼ぶ。イベント送信ラッパーは同意前には何もしない
- `src/app/api/waitlist/route.ts`: `POST`。メール検証（形式・254 文字以内）。隠し項目が埋まっていれば保存せず成功を返す。`error.code === "23505"`（重複）も成功扱い、それ以外は 500。`.insert()` に `.select()` を付けない（付けると SELECT 権限が要る）
- `src/lib/supabase-server.ts`: `import "server-only"`。サーバー専用の `sb_secret_` キーで insert する（RLS を通らないので、公開 API 側はテーブルを完全に閉じられる）
- `supabase/waitlist.sql`: テーブル（email, locale, source, created_at）、`lower(email)` の一意索引、RLS 有効でポリシーなし。`anon`/`authenticated` からは revoke し、`service_role` にだけ insert を grant する（2026-10-30 から新規テーブルは明示的な GRANT が必要になる。公開キーでは読み書き不可 = AC13）
- `src/app/[lang]/privacy/page.tsx`: 日英。運営者名・連絡先はプレースホルダー
- `next.config.ts`: PostHog 用の `/ingest` rewrites（広告ブロッカーによる計測の取りこぼしを減らす。PostHog 推奨）と `skipTrailingSlashRedirect: true` を追加する。既存の `cacheComponents` などはそのまま
- `.env.example`: `NEXT_PUBLIC_POSTHOG_KEY`、`NEXT_PUBLIC_POSTHOG_HOST`、`SUPABASE_URL`、`SUPABASE_SECRET_KEY`（値はプレースホルダー）

追加する依存（仕様どおり、バージョンは固定）: `tone@15.1.22`（`latest` タグの安定版。`next` タグの 15.5 系は公開から 1 日なので使わない）、`posthog-js@1.438.x`、`@supabase/supabase-js@2.118.x`。posthog-js の依存 `core-js` に寄付メッセージ表示だけの postinstall があるので、`allowScripts` では deny にする。Tone（約 77KB gzip）と PostHog（約 103KB gzip）は動的 import にして、初期表示のバンドルに含めない。

## 仕様の更新（手順 0 で `docs/specs/...` に反映する）

- 追加（ユーザー確認済み）: 再生時のみのコード伴奏（ON/OFF）、8 候補の連続再生。書き出す MIDI はメロディのみのまま
- AC7 の定義を「(音高, 開始) の集合で `2·|C∩P| ≥ |C|`、子の音数は主の親の ±25% 以内」と明記する
- MIDI はスウィングをかけずにクオンタイズしたまま書き出す（Design notes の「書き出し時にもスウィング」を変更）。DAW 側で好きなグルーヴをかけられ、AC8 とも素直に合う
- Design notes のエンジン構成を、上の平坦な音符列の方針に差し替える
- 制約として明記: 16 分グリッドなので、Trap で多用される 3 連符は今回は表現できない

9. 音声: `player.ts`（単体再生、連続再生、コード伴奏、iOS 対応）
10. MIDI ダウンロード（`Blob` + `<a download>`）、ファイル名 `melobreed-<preset>-<key><scale>-<bpm>bpm-g<世代>-<n>.mid`
11. 同意バナーと PostHog、6 イベント、`/ingest` rewrites
12. Pro モーダル、ウェイトリスト API、SQL、`.env.example`
13. プライバシーポリシー
14. 全体検証と `npm run build`。`reviewer` サブエージェントで仕様の AC と照合し、ルートハンドラーとキーの扱いは `/security-review` にかける

## Verification

- 自動: `npx vitest run src/engine`（AC5〜AC8）、辞書キーと言語判定のテスト（AC1）、`npm run verify`、`npm run build`
- 手動（`npm run dev`）:
  - iOS Safari・Android Chrome で、試聴・連続再生・コード伴奏・選択・書き出しを確認する（AC3、AC4、AC14）
  - GarageBand ともう 1 つの DAW で .mid を読み込む（AC8）
  - DevTools で、同意前に PostHog への通信が一切ないことを確認する（AC10）。PostHog のライブイベントを確認する（AC11）
  - Supabase に行が入ること、公開キーでは select できないことを確認する（AC12、AC13）
  - 外部サービスの確認は、ユーザーが Supabase と PostHog のプロジェクトを作り、環境変数を設定してから行う

## リスクとロールバック
